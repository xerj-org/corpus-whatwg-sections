WHATWG URL — section host-writing — Host writing

<h3 id=host-writing oldids=host-syntax>Host writing</h3>

<p>A <dfn export oldids=syntax-host>valid host string</dfn> must be a <a>valid domain string</a>, a
<a>valid IPv4-address string</a>, or: U+005B ([), followed by a
<a>valid IPv6-address string</a>, followed by U+005D (]).

<p>A <a for=/>string</a> <var>input</var> is a <dfn>valid domain</dfn> if these steps return true:

<ol>
 <li><p>Let <var>domain</var> be the result of running <a>domain parser</a> with <var>input</var>
 and true.

 <li><p>If <var>domain</var> is failure, then return false.

 <li><p>If running the <a>ends in a number checker</a> on <var>domain</var> returns true, then
 return false.

 <li><p>Return true.
</ol>

<p class=XXX>Ideally we define this in terms of a sequence of code points that make up a
<a>valid domain</a> rather than through a whack-a-mole:
<a href=https://github.com/whatwg/url/issues/245>issue 245</a>.

<p>A <dfn export oldids=syntax-host-domain>valid domain string</dfn> must be a string that is a
<a>valid domain</a>.

<p>A <dfn export oldids=syntax-host-ipv4>valid IPv4-address string</dfn> must be four shortest
possible strings of <a>ASCII digits</a>, representing a decimal number in the range 0 to 255,
inclusive, separated from each other by U+002E (.).

<p>A <dfn export oldids=syntax-host-ipv6>valid IPv6-address string</dfn> must be one of the
following:

<ul class=brief>
 <li><p>a <a>valid IPv6-pieces string</a> with <a>effective piece length</a> 8.
 <li><p>a <a>valid IPv6-pieces-and-IPv4 string</a> with <a>effective piece length</a> 8.
 <li><p>U+003A U+003A (::), optionally preceded by a <a>valid IPv6-pieces string</a>, and
 optionally followed by either a <a>valid IPv6-pieces string</a> or a
 <a>valid IPv6-pieces-and-IPv4 string</a>, such that the sum of the <a>effective piece lengths</a>
 of the preceding and following strings is at most 7.
</ul>

<p>A <dfn>valid IPv6-pieces-and-IPv4 string</dfn> is either a <a>valid IPv6-pieces string</a>,
followed by U+003A (:), followed by a <a>valid IPv4-address string</a>; or a
<a>valid IPv4-address string</a> alone.

<p>A <dfn>valid IPv6-pieces string</dfn> is one or more <a>valid IPv6-piece strings</a>, separated
from each other by U+003A (:).

<p>A <dfn>valid IPv6-piece string</dfn> is a shortest possible string of <a>ASCII hex digits</a>,
representing a hexadecimal number in the range 0 to 0xFFFF, inclusive.

<p>The <dfn>effective piece length</dfn> of a <a>valid IPv6-pieces string</a> is the number of
<a>valid IPv6-piece strings</a> it contains. The <a>effective piece length</a> of a
<a>valid IPv6-pieces-and-IPv4 string</a> is the number of <a>valid IPv6-piece strings</a> it
contains, plus 2.

<p class=note>This is derived from
<cite>A Recommendation for IPv6 Address Text Representation</cite>. For consistency with IPv4
leading zeros are not allowed. [[RFC5952]]

<p>A <dfn export>valid opaque-host string</dfn> must be one of the following:

<ul class=brief>
 <li><p>one or more <a>URL units</a> excluding <a>forbidden host code points</a>
 <li><p>U+005B ([), followed by a <a>valid IPv6-address string</a>, followed by U+005D (]).
</ul>

<p class=note>This is not part of the definition of <a>valid host string</a> as it requires context
to be distinguished.
